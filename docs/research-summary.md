# Research summary — 0.0.3

0.0.3 is a cut-regression review over 0.0.1 and 0.0.2, plus a focused audit of the supplied `ag-opencode-skills` inspirational collection and current Claude Code skill/plugin documentation.

## Findings

1. **0.0.2 cut the right large thing but compressed some distinctions too far.** Domain-specific skill guidance survived; the lost value was mainly execution discipline around repository intake, lifecycle ownership, failure classification and runtime proof.
2. **Restoration should be progressive, not duplicated.** Re-adding the old seven-rule block to 33 skills would undo the routing/body optimization. 0.0.3 moves the recovered execution contract behind a direct skill reference read only for repository-changing tasks.
3. **Descriptions remain the highest routing-cost surface.** 0.0.3 leaves the 0.0.2 description compression unchanged and relies on positive + overlap evals rather than verbose self-description.
4. **The new inspirational source reinforces explicit activation boundaries and machine validation.** Its `When to use` / `When NOT to use`, categories, tags and validation ideas are useful; its persona-heavy monoliths, forced model field and universal modern-version assumptions are not.
5. **One skill per activation intent remains superior to framework-version duplication.** Exact target version is resolved from the project and official docs; version matrices are navigation aids.
6. **Minecraft still requires stronger domain rules than generic Java skill packs.** Classloading-safe multiversion isolation, Folia ownership, PacketEvents thread/context boundaries and client-visible-state semantics remain dedicated skills/references.
